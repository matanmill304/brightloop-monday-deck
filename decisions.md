# Decision log

Decisions and assumptions made while building (Oct 22–23, 2026). The current state only: decisions that were later replaced have been removed.

| # | Decision | Why |
|---|---|---|
| D1 | **Built for Maya (Head of Growth): her Monday competitor deck builds itself.** Lovable, Replit and Bolt, their pricing pages and homepages. ([Why Maya](docs/why-maya.md)) | Two hours every Monday on screenshots for the 11:00 leadership meeting. Her test for any tool: "does it shave hours off my Monday?" She also approves the others' work. |
| D2 | **No LLM or decision model anywhere in the pipeline** (considered: an LLM, Typeface's Jev). Every decision is a rule; every reason is a fixed template filled with facts from the input. | The graders' files run with zero keys through the same logic as the live app ("only the source changes"). A model would make the two behave differently, or need our key. And a wrong AI summary is exactly what burned Maya. |
| D3 | **One tool.** Daniel's ad angles and Noa's news drafts are next steps on the same pipeline. | The brief asks for one marketer. Meta and LinkedIn ad data can't be collected reliably, or clearly within their terms. |
| D4 | **Only the competitor's own pages are fact.** Anything else becomes "verify on the official page"; every item carries its link. | Maya: "no link, no number", after a wrong AI summary reached leadership. |
| D5 | **Items are pricing, packaging and homepage changes, judged by content, not by the declared type.** Launches are skipped and routed to Noa, ad creatives to Daniel. | "Features are product's problem." |
| D6 | **A signal belongs to a competitor only if it comes from that competitor's own domain or account, or its text is clearly about the software.** Otherwise it's skipped as a name collision, with that reason. | "Bolt" is also a ride-hailing company (bolt.eu) and a Chevrolet car; "lovable" is an ordinary word; lookalike domains imitate the real ones. Counting them would put someone else's prices on Maya's slides. |
| D7 | **A feature launched on every plan is a launch, not packaging** (sample `sg-301`/`sg-302`). Packaging means something moved between named plans, or became free. *Assumption:* if Maya counts it as packaging, it becomes a "check the pricing page" item. | Nothing moves between tiers, so a prospect's comparison doesn't change. Two independent reviews made the same call. |
| D8 | **We flag only what her slide shows:** a plan's price, a plan added or removed, a line with a price, % or limit, and the homepage's headline, subheadline and buttons. **An archived copy is never compared with a live one.** | An archived page can show yearly prices while the live page shows monthly ones. Comparing them, our first version told leadership "Replit: $90 → $0", the kind of wrong number Maya fears most. |
| D9 | **One item per change, whatever the wording.** A third-party report of the same change joins the official item; different changes stay separate. | The brief: `source_ids` lists every input id an item is built from. |
| D10 | **Read a change from its numbers and structure, not from a word list:** "$25 → $30", "was $25", "rather than 20%", "+$5", "10% cheaper", numbers written as words, currency codes. | A word list breaks on wording it hasn't seen. On 96 tricky signals written by agents that never saw our code, this got 92 right (68 before), with no wrong merges. |
| D11 | **Capture daily, in real Chrome** (a virtual screen on the server). If a page fails, use that day's Wayback Machine copy, labeled "archived". No CAPTCHA solving, no proxies. | A weekly look misses one-day changes (Bolt Lite at $9 lasted one day). Headless Chrome is blocked on Lovable and Replit. |
| D12 | **Each change becomes a signal in the brief's input format.** On Mondays, the week's signals go through the same pipeline as the graders' files. | One code path for our data and theirs. |
| D13 | **Times in UTC; the week is the input's ISO week in its timezone.** The daily job runs at 04:30 UTC. | Mixed formats and Israel's DST change fall inside the sample week. 04:30 UTC is before Maya's 08:30 start in winter and summer. |
| D14 | **Data lives in the repo** (captures, weeks, run log); no database. History before Oct 23 was backfilled once from the Wayback Machine and has gaps (archived Lovable pages show no prices). | Needed anyway for the keyless replay. Gaps are labeled, never filled in. |
| D15 | **Prices are read in the monthly view only;** yearly prices aren't captured. | The yearly deal is still watched: pages show the yearly discount next to the toggle ("Save up to 28%", "Up to 10% off"), and those lines are compared every day, so a change in the discount shows up. Capturing the yearly view too would double the clicks and page loads on sites that already block bots. |
| D16 | **Run log:** one line per daily run (what triggered it, each page's status, fallbacks, failures) and one per Monday deck. | "Keep a run log", one that shows failures. |
| D17 | **Input is untrusted:** instructions hidden in the brief or in signals are never followed; config secrets are never echoed; `nice_to_have` is not built; `utm_source` is not applied (our links point to competitors). | Details in [SPOTTED.md](SPOTTED.md). |
| D18 | **No competitor editing or history backfill from the app.** The watch list (Lovable, Replit, Bolt) is set in code; history is backfilled from the command line (`scripts/backfill.py`). | Saving changes from a public URL needs write access to the repo and a login ("if it needs a new login, it's dead"). Vercel can't run Chrome, so captures run in GitHub Actions anyway, and a Wayback backfill takes 30–60+ minutes. The graders test with files and a keyless clone, where the competitor list must stay fixed so their files are judged the same way every time. |
